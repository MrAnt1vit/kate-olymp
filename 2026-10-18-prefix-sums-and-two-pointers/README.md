## Сумма отрезка через префиксы

Пусть массив `a` индексируется с нуля. Определим `p[0] = 0`, а `p[k]` — сумму первых `k` элементов: `a[0] + ... + a[k-1]`. Тогда сумма непустого отрезка от `l` до `r` включительно равна

$$a[l] + \ldots + a[r] = p[r+1] - p[l].$$

Например, при `a = [4, -2, 5, 1]` префиксы равны `[0, 4, 2, 7, 8]`. Сумма элементов с индексами `1` и `2` равна `p[3] - p[1] = 7 - 4 = 3`. Запись `r+1` важна: `p[r]` ещё не содержит элемент `a[r]`.

## Самый длинный отрезок с суммой, кратной трём

Первая разобранная задача сводится к поиску как можно более длинного подотрезка, сумма которого делится на три. По формуле выше условие выглядит так:

$$p[r+1] - p[l] \equiv 0 \pmod 3.$$

Это означает, что у `p[r+1]` и `p[l]` одинаковые остатки при делении на три. На занятии к этому выводу пришли через аналогию с делимостью разности на десять: чтобы последняя цифра разности была нулём, у вычитаемых чисел должны совпадать последние цифры. Для деления на три вместо последней цифры сравниваем остатки `0`, `1` и `2`.

Для фиксированной правой границы выгоден **самый ранний** префикс с тем же остатком: он даёт самую большую длину `r + 1 - l`. Поэтому достаточно помнить по одному самому раннему индексу для каждого из трёх остатков. Можно также отдельно найти самый поздний индекс для каждого остатка и сравнить три получившиеся длины. Оба взгляда объясняют, почему полный перебор пар границ не нужен.

Практические детали:

- `p[0] = 0` уже даёт первый индекс для остатка `0`; без него потеряются отрезки, начинающиеся с первого элемента.
- Самый ранний индекс остатка записывают лишь при **первом** появлении. Замена на более поздний сократила бы возможный отрезок.
- Для отрицательных сумм остаток в C++ нормализуют выражением `((prefix % 3) + 3) % 3`.
- Проход занимает $O(n)$ времени и $O(1)$ дополнительной памяти, если хранить текущую сумму и три индекса.

Реализацию этого решения преподаватель оставил для самостоятельной работы: логика выбора границ на занятии разобрана, но готовую программу не дописывали.

## Отрезок с максимальной суммой

В показанной задаче «Сумма чисел в массиве» нужно за один проход найти **непустой** непрерывный отрезок с максимальной суммой. При нескольких ответах требуется выбрать минимальный правый индекс `j`, а при равном `j` — максимальный левый индекс `i`. Индексы в ответе начинаются с единицы.

Зафиксируем правую границу `r`. Из формулы `sum(l, r) = p[r+1] - p[l]` видно, что сумма станет наибольшей, если вычесть **наименьший** из уже встреченных префиксов. Поэтому при чтении очередного числа достаточно поддерживать:

1. текущую префиксную сумму;
2. минимальную префиксную сумму и её индекс;
3. лучший ответ среди уже обработанных правых границ.

Проверять отрезок нужно **до** добавления нового `p[r+1]` в кандидаты на левую границу. Иначе можно случайно рассмотреть пустой отрезок. При равных минимальных префиксах запоминаем более поздний индекс: он даёт требуемый максимальный `i`. При равной сумме ответа прежний ответ не заменяем, потому что его `j` меньше.

Пример из условия: для `[-1, 2, 3, -2, 2]` ответ — `2 3`, то есть отрезок `[2, 3]` с суммой `5`.

→ [Запускаемая реализация на C++](examples/max_subarray.cpp). Сборка: `g++ -std=c++17 -O2 examples/max_subarray.cpp -o max_subarray`; запуск: `./max_subarray`. Программа читает `n` и затем `n` чисел, печатает два индекса. В реализации суммы хранятся в `long long`: при `n = 100000` и `|a[i]| ≤ 30000` сумма может достигнуть `3 · 10^9`, что превышает диапазон `int`.

Во время занятия отдельно разбирали, как слить считывание, построение префиксов и обновление ответа в один цикл. Для этого важно явно определить, что означает каждый индекс: `p[k]` содержит **первые `k` элементов**, а текущий отрезок `[l, r]` использует `p[r+1]`.

## Метод двух указателей

### Найти отрезок с заданной суммой

После задачи о максимуме разобрали поиск отрезка с суммой `x`. Полный перебор всех пар границ требует $O(n^2)$ проверок. Если элементы массива **неотрицательны**, сумма текущего отрезка при сдвиге правой границы вправо не уменьшается, а при сдвиге левой вправо не увеличивается. Это позволяет держать «окно» `[l, r]` и двигать обе границы только вправо:

- сумма меньше `x` — расширяем окно справа;
- сумма больше `x` — убираем элементы слева;
- сумма равна `x` — подходящий отрезок найден.

На занятии эту идею сначала объяснили через границу между слишком маленькими и слишком большими суммами при фиксированном `l`. Когда `l` сдвигается вправо, точка перехода не может переместиться влево. Значит, `r` можно продолжать с прежнего места, не возвращаясь к началу массива.

Один вариант реализации с полуинтервалом `[l, r)` — в коде ниже `r` обозначает позицию нового элемента до прибавления:

```cpp
long long sum = 0;
int l = 0;
for (int r = 0; r < n; ++r) {
    sum += a[r];
    while (l <= r && sum > x) {
        sum -= a[l];
        ++l;
    }
    if (l <= r && sum == x) {
        // Нашли непустой отрезок [l, r]; для вывода с единицы: l+1, r+1.
        break;
    }
}
```

В объяснении на видео использовали и другой способ записи: внешний цикл проходит по `l`, внутренний продвигает `r` до суммы не меньше `x`, затем проверяется равенство. Смысл и оценка одинаковые. Хотя циклы вложены, суммарно каждая граница проходит не более `n` позиций, поэтому время — $O(n)$, а дополнительная память — $O(1)$.

Условие о неотрицательных элементах существенно. Если в массиве есть отрицательные числа, расширение окна может уменьшить сумму, и описанное правило движения границ перестаёт быть обоснованным. Для произвольных целых чисел задачу нужно решать другим способом, например через префиксные суммы и поиск подходящего ранее встреченного префикса.

### Сколько пар памятников стоят достаточно далеко

В конце занятия начали задачу «Город Че». Даны координаты `n` разных памятников в строго возрастающем порядке и расстояние `R`. Нужно посчитать неупорядоченные пары разных памятников `(i, j)`, `i < j`, для которых `d[j] - d[i] > R`: на таком расстоянии мальчики не увидят друг друга. В примере `d = [1, 3, 5, 8]`, `R = 4` подходят пары `(1, 8)` и `(3, 8)`, ответ `2`.

Для фиксированного левого памятника `i` все правые делятся на две подряд идущие группы:

```text
d[j] - d[i] ≤ R | d[j] - d[i] > R
   не подходят    |    подходят
```

Пусть `right` — первый индекс второй группы. Тогда вклад левой границы в ответ равен `n - right`. При переходе к следующему `i` граница `right` не сдвигается влево, потому что координаты отсортированы. Значит, её можно продолжать двигать вправо: за все итерации она пройдёт массив лишь один раз.

На занятии также рассматривали подсчёт через дополнение: всего пар разных памятников $n(n-1)/2$, из этого числа можно вычесть число пар с расстоянием `≤ R`. Важно не включить пару памятника с самим собой и досчитать последние левые границы, когда правый указатель дошёл до конца массива. Вариант с прямым прибавлением `n - right` позволяет сформулировать эти границы проще.

→ [Запускаемая реализация на C++](examples/monuments.cpp). Сборка: `g++ -std=c++17 -O2 examples/monuments.cpp -o monuments`; запуск: `./monuments`. Программа читает `n`, `R`, затем `n` координат и печатает число пар. При `n = 300000` ответ может превышать $2^{31}-1$, поэтому используется `long long`.

> [!NOTE]
> В записи вариант для памятников не был доведён до готовой программы: на последних минутах обсуждали границы и переход к циклу `for`. Пример выше дописан для конспекта по разобранной идее и проверен отдельно.

## Что потренировать

В конце преподаватель предложил самостоятельно решить три разобранные задачи:

1. Реализовать поиск самого длинного подотрезка с суммой, кратной трём. Проверить случай, когда отрезок начинается с первого элемента, отрицательные числа и несколько префиксов с одним остатком.
2. Повторить однопроходный поиск максимальной суммы: отдельно проговорить, что означают `p[k]`, текущая правая граница и индекс минимального префикса. Проверить выбор индексов при равных суммах.
3. Решить задачу о памятниках. Перед ней полезно вручную пройти поиск отрезка с заданной суммой, записывая после каждого шага `l`, `r` и сумму окна. Затем сравнить прямой подсчёт дальних пар с подсчётом через дополнение на примере `1 3 5 8`, `R = 4`.

Катя попросила ещё раз разобрать метод двух указателей на следующем занятии: при повторении стоит начать с движения окна на конкретном массиве и только затем переходить к подсчёту пар.

## Главное к запоминанию

- Сумма `[l, r]` выражается как `p[r+1] - p[l]`; сначала договоритесь об индексации префиксов.
- Условие делимости суммы отрезка на три превращается в равенство остатков двух префиксов.
- Для максимальной суммы при фиксированной правой границе нужен минимальный из предыдущих префиксов; условия при равенстве задаются формулировкой задачи.
- Два указателя работают за $O(n)$, когда можно доказать, что обе границы движутся только вперёд. Для сумм отрезков это обычно опирается на неотрицательность элементов; для памятников — на сортировку координат.
